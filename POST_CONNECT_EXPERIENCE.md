# Keragon Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Ops-менеджер в health-tech/wellness компании, использующий Keragon как HIPAA-совместимую
no-code платформу автоматизации между медицинскими и общими SaaS-системами (аналог
Zapier, но с фокусом на здравоохранение).

## 2. Момент истины после подключения
Сразу после `connect_keragon` — список workflows с их статусом (активен/на паузе) — видно,
какие автоматизации между медицинскими системами реально работают.

## 3. Что пользователь видит
- Workflows (визуальные автоматизации) и их статус — `list_workflows`, `get_workflow`.
- Историю выполнений workflow, включая ошибки по шагам — `list_workflow_runs`.
- Подключения к внешним системам (EHR, CRM, коммуникационные каналы) — `list_connections`.
- Шаблоны workflow для типовых медицинских сценариев (напоминание о приёме, follow-up) —
  `list_templates`.
- Логи обработки данных пациента (для HIPAA-аудита) — `get_workflow_audit_log`.

## 4. Чем пользователь может управлять
- Включать/выключать workflow — `activate_workflow`, `deactivate_workflow`.
- Запускать workflow вручную для теста — `test_workflow`.
- Создавать workflow из готового медицинского шаблона — `create_workflow_from_template`.
- Повторно обрабатывать неудачный запуск — `retry_workflow_run`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'какие автоматизации напоминания о приёме сейчас выключены?'.
Она находит через `list_workflows`, а я прошу включить нужную — `activate_workflow`
делает это с полным HIPAA-совместимым аудиторским следом."

## 6. Что делает это "заточенным под него"
`get_workflow_audit_log` даёт РЕАЛЬНЫЙ аудиторский след обработки данных пациента именно
этой организации — критичное требование комплаенса в здравоохранении, которого нет у
обычных no-code платформ типа Zapier.
