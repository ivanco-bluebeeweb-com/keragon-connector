# Keragon Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: healthcare
automation инженер, использующий Keragon как no-code workflow движок поверх HIPAA-
совместимых интеграций.

## 1. Credential type
ОСОБЫЙ класс — не `connect_*` в привычном смысле, а ДВУНАПРАВЛЕННЫЙ webhook-мост:
исходящий (мы шлём в Keragon workflow URL) + входящий (Keragon шлёт нам на наш URL с
секретом). Это принципиально другой онбординг-паттерн, чем API-key/OAuth коннекторы.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` с ДВУМЯ явными карточками с самого начала:
   "Отправлять события В Keragon" и "Получать события ИЗ Keragon" — не одна форма, а
   явное разделение направлений, т.к. пользователю может быть нужно только одно.
2. **Исходящее направление** — форма "Название моста" + "URL вебхука Keragon workflow"
   (со ссылкой на Keragon UI, где скопировать этот URL).
3. **Входящее направление** — сразу видимый НАШ webhook URL для копирования (карточка
   §6 из общего стандарта: `Input(readonly) + Button("Копировать")`) + секрет для
   валидации подписи, со ссылкой "вставьте это в свой Keragon workflow".
4. **После настройки моста** — журнал последних отправленных/полученных событий сразу
   виден, чтобы можно было проверить, что интеграция реально работает (а не просто
   "конфигурация сохранена").
5. **Тестовая отправка** — идеально: кнопка "Отправить тестовое событие" для проверки
   исходящего моста сразу после создания, не дожидаясь реального workflow-триггера.
