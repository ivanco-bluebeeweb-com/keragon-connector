## Прогон 2026-08-21 — Части A-C (персона, данные, сценарии) + Часть D

**Персона:** владелец Keragon-аккаунта (единственная функциональная роль
этого приложения — многомостовой двунаправленный webhook-мост, не
полноценный CRUD-коннектор, см. `CONNECTOR_DISCOVERY.md` §3). Он
регистрирует именованные исходящие мосты (по одному на каждый Keragon
workflow с HTTP Webhook Trigger), запускает их вручную или пачкой, и
настраивает общий секрет, чтобы шаг "HTTP Client action" внутри workflow
мог присылать события обратно в Imperal. Вариативность сценариев — из
классов данных (пусто/типично/граница/невалидно/экзотика), не из ролей.

**5 обязательных веток покрыты** (см. `tests/test_pst_scenarios.py`,
27 тестов):

1. **Empty** — ничего не настроено: `list_outgoing_bridges`,
   `get_inbound_webhook_config`, `list_inbound_events`,
   `audit_bridge_health` без данных, `send_bridge_event` без мостов — все
   дают честный, понятный ответ, не падение.
2. **Typical** — happy path: создать мост → он появляется в списке;
   отправить событие через реальный HTTP-вызов (успех); сгенерировать
   входящий секрет; принять валидный POST с верным заголовком
   `X-Keragon-Webhook-Secret`; массовая рассылка на два моста разом
   (`bulk_send_bridge_event`).
3. **Boundary** — регистронезависимый заголовок секрета; пустое тело
   запроса не роняет приёмник; `event_kind`/`bridge_id` корректно читаются
   из query-параметров (не только из JSON body); обрезка лога инбаунд-
   событий по кап (протестировано на уменьшенном лимите для скорости).
4. **Invalid** — URL без `http(s)://` префикса отклоняется ДО сохранения;
   пустое имя моста отклоняется; неверный/отсутствующий секрет отклоняется
   `hmac.compare_digest`; обращение к несуществующему id моста — понятная
   ошибка, не `KeyError`.
5. **Exotic / Soap Opera** — сетевой сбой при отправке (DNS/timeout) и
   не-2xx ответ от Keragon конвертируются в контролируемую ошибку, не в
   необработанное исключение; частичное обновление моста (только имя) не
   затирает URL; удаление моста делает последующий `send_bridge_event` по
   тому же id ошибкой; повторная доставка одного и того же payload
   (retry после timeout) намеренно создаёт ВТОРУЮ запись — задокументировано
   как осознанное поведение (ответственность за идемпотентность — на
   стороне Keragon workflow); ротация секрета мгновенно отклоняет старый;
   один невалидный id в bulk-вызове не прерывает обработку остальных;
   полный жизненный цикл (создать мост → выстрелить → настроить inbound →
   принять callback → ротация → аудит здоровья) проходит целиком, и
   `audit_bridge_health` корректно относит мост, получивший callback, к
   "не тихим".

**D1 (Deploy Verification):** `imperal validate .` → 0 error / 1 warning
(V8, ожидаемо для CLI без полного filesystem-контекста) / 1 info
(отсутствие `@ext.on_install`, ожидаемо для этого моста — нет данных,
которые требовали бы инициализации при установке).

**D2 (Idempotency):** явный тест на повторную доставку одного и того же
inbound-события (Branch 5) — подтверждено намеренное поведение «не
дедуплицируется»; отдельный тест на ротацию секрета дважды подряд.

**D3 (Security/SSRF):** исходящая сторона (`create_outgoing_bridge` /
`send_bridge_event` / `bulk_send_bridge_event`) — та же осмысленная,
уже принятая SSRF-поверхность, что и в Zapier Webhook / Make.com
Connector: URL — это и есть credential, настраивает его сам владелец
аккаунта для собственного Keragon workflow, не приём произвольного
адреса от третьей стороны. Входящая сторона (`receive_keragon_webhook`)
защищена `hmac.compare_digest` constant-time сравнением общего секрета —
по тому же паттерну, что Zapier Webhook / Slack Connector используют для
проверки подписи.

**D4 (Regression grep):** проверено, что оба известных бага-паттерна из
`Docs/known-bug-patterns.md` (запись 2026-08-20) не повторены в этом
приложении — `ActionResult.success(...)` везде вызывается с обязательным
`summary`, и чтение постранично идёт через `page.data`, не `page.items`.

**Итог:** 27/27 тестов проходят (`tests/test_pst_scenarios.py` +
`tests/conftest.py`), `imperal validate .` чист (0 ошибок).
